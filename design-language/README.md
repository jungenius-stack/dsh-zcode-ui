# ZCode 设计语言知识库（design-language）

> 来源：ZCode 3.16.x 活页面 CDP 实测 + app.asar bundle 源码反解 + 2026-10-26 六轮踩坑对照验证。
> 目标：dsh-zcode-ui 以此为唯一设计基准，做到「一比一继承 ZCode 的设计语言与设计逻辑，含细微细节」，并按 DSH 宿主实际约束做显式调整（调整必须写明原因）。

## 文件索引

| 文件 | 内容 | 何时读 |
|---|---|---|
| `tokens.json` | 231 个 CSS 变量的双主题全量对照（light/dark resolved 值） | 任何颜色/边框/表面取值前 |
| `01-design-tokens.md` | 核心令牌速查 + 主题映射逻辑 + DSH 侧映射与缺口 | 动颜色之前 |
| `02-motion.md` | 时长、缓动、滚动曲线、reduced-motion、性能预算 | 任何动画/滚动实现前 |
| `03-turn-navigator.md` | 轮次导航 24 格全状态矩阵（首个完整组件范例） | 改轮次导航；作为其他组件的规格写法范例 |
| `04-open-gaps.md` | 当前待修清单（带判定表验证器），每轮评判后更新 | **每次开工先读这个** |
| `05-extraction-method.md` | CDP 探针模板 / asar 反解方法 | 需要本文档没覆盖的细节时自助提取 |
| `audit-scripts/` | 双端 CDP 探针脚本（几何/hover/点击/主题/键盘） | 验证器执行、自查 |

## 工作契约（重要）

1. **完成哨兵**：每轮整改全部完成（含门禁绿）后，在最终回复的**末尾**单独一行输出：
   `【设计语言整改完成】`
   对面有自动监控在盯这个哨兵触发独立评判；没有哨兵时兜底检测「门禁全绿+修复清单」，但哨兵最可靠。
2. **修一条验一条**：`04-open-gaps.md` 每条都带判定表（输出 X⇒坑成立 / Y⇒已修）。修完必须跑验证器并回填结果，禁止「改了没验」（历史教训：坑 3 曾改了没验，靠对方补测才闭环）。
3. **几何对比先统一参照物**：跨端对比必须选「两端结构等价的锚点」（如刻度左缘而非 nav 左缘——两端 nav 内边距不同，教训见报告五坑 1）。
4. **深浅双主题都要验**：任何颜色/可见性改动，深色浅色各截屏目检一次（教训：写死黑色在深色下隐形）。
5. **压缩上下文前先落盘**：把当前进度（已修/未修/验证结果）写进 `04-open-gaps.md` 的执行记录区，防止会话压缩丢状态。
6. **DSH 约束的显式调整**：ZCode 做了但宿主能力不支持时（如刻度无 running 标记），在 `03-turn-navigator.md` 对应格标注「DSH 约束调整」并写明原因，不得静默跳过。
7. **结构债预算**：`!important` 有预算（当前 52）；需要加时在测试文件里带日期注释说明理由。

## 演进规则

- 每轮评判（T2 深审）后：已修条目从 `04` 清零并移入「已闭环」区；新发现的坑追加进 `04`；新提取的 ZCode 细节合入 `01/02/03`。
- 组件成熟判据：连续 2 轮 T2 无新增 🐯 + 矩阵全 ✅（豁免格需标注）+ 门禁绿 + 双主题目检过。
- 下一个组件（sidebar / composer / …）开工时，按 `03` 的格式新建 `0N-<component>.md` 矩阵。
