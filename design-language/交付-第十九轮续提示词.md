你上一轮在「先实测验证主题切换机制」处被中断（`interrupted`）。两件事：

**① 你对我的说法提出质疑是对的，我把话说窄了。** 实测 grep 表明：
- 插件自己用 **两套**：`data-ds-dark-theme` 27 处 + `theme-zai-dark` 13 处 + `theme-zai-light` 5 处；
- 宿主令牌层跟随 `body[data-ds-dark-theme]`。
所以只改 html class 会让「插件自己的规则」翻到浅色、但「宿主令牌」仍是深色 —— 两边不同步，肉眼看就像"没切成功"。**完整切主题要么走设置页 UI，要么同时改 `body` 属性 + html class。** 这条已更正。

**② TA1 的目标值不对，必须改。** 你写的是「取中值 #f7f7f7（247）」，但 ZCode 是分层的：

```
--color-sidebar     浅色 oklch(97%  0 0) → rgb(245) = #f5f5f5   ← 侧栏列
--color-background  浅色 oklch(98.5% 0 0) → rgb(250) = #fafafa   ← 内容画布
```

换算已交叉验证：公式 `Y=L³ → sRGB` 反算 `oklch(87%)→#d4d4d4`、`oklch(37.1%)→#404040`，与我们早已锁定的深色前景 212 / G14 浅色基色 #404040 **完全吻合**，所以 97%→#f5f5f5、98.5%→#fafafa 可信。

**所以一比一的目标是：侧栏列 #f5f5f5、内容画布 #fafafa（不是两者取中值 247）。** 取中值会让侧栏偏亮 2 通道、画布偏暗 3 通道，两头都不准。

本轮完成：

1. 把 TA1 目标改为分层值（侧栏 #f5f5f5 / 画布 #fafafa），改完重算 G14（你上轮已推过「对比度只升」，确认即可）。
2. **走设置页 UI 切主题**验证浅色（不要只改 class）：设置页 owner 事件 → 外观分区 → 切浅色 → 量侧栏列与内容画布两处的 computed 背景 → 切回深色。
3. 验证器：浅色侧栏 = rgb(245,245,245)±1、画布 = rgb(250,250,250)±1；G14 三档对比度不回退（sec ≥6.0:1 / ter ≥4.5:1）。
