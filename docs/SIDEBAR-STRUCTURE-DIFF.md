# 侧栏结构与 ZCode 的差异声明

## 为什么要有这份文档

本插件把 DSH Web 的侧栏换成 ZCode 的视觉语言（几何、色板、图标、动效），
但**侧栏的信息结构并未完全对齐 ZCode**。

如果不把这件事写清楚，后续维护者看到「结构不一样」，很容易误判为
「还原不彻底」并去「修复」它——而其中相当一部分差异是 DSH 数据模型决定的，
改不动，也不该改。

因此本文档逐条声明：**哪些差异是有意保留、哪些受宿主约束、哪些确实待办**。

来源：`docs/ZCODE-DESIGN.md` §5（ZCode 侧栏布局提取）、评审报告 §3.4。

---

## 一、逐维度对照

| 维度 | ZCode | 本插件 | 性质 |
| --- | --- | --- | --- |
| 折叠轨内容 | 仅 logo + 展开按钮 | 12+ 个图标按钮（新建/搜索/专家/技能/插件/连接器/定时/助理） | 有意保留 |
| 顶部构成 | NewTaskButtonGroup + 整行搜索按钮 | 品牌按钮 + 折叠/搜索图标 + 主菜单 | 部分差异 |
| 二级导航 | 无「扩展」分组 | 有「扩展」折叠组，内含 6 个扩展入口 | 有意保留 |
| 列表分区 | Projects / Conversations 两个可折叠分区 | 任务 / 频道 / 定时 三个 tab | 受宿主约束 |
| 任务分区 | 置顶区 / 时间线区 / 分组区 / 归档区 四区并存 | 工作区 → 会话树（两级树） | 受宿主约束 |
| 置顶 / 分组的对象 | **任务**（task） | **项目 / 工作区**（workspace） | 受宿主约束，语义相反 |
| 分组能力 | 组颜色、sticky 组头、拖任务入组、空组投放区、虚拟列表 | 项目分组（缺组颜色、sticky 组头、虚拟列表） | 确实待办 |

## 二、逐条说明

### 2.1 折叠轨内容（有意保留）

ZCode 的折叠轨只放 logo 与展开按钮，因为它的主要操作在展开态即可触达。
本插件保留 12+ 个图标按钮，原因：

- DSH 的功能入口（专家 / 技能 / 插件 / 连接器 / 定时 / 助理）**没有其他常驻可达路径**，
  折叠后若一并隐藏，用户在窄侧栏下无法触达这些功能；
- 这些入口在 DSH 原生侧栏中本就是图标列表，保留它们是与宿主功能面一致的取舍。

**取舍**：优先「功能可达」而非「与 ZCode 逐像素一致」。

### 2.2 「扩展」二级分组（有意保留）

ZCode 没有二级分组。本插件把 6 个扩展类入口收进「扩展」折叠组，因为
DSH 的扩展入口数量超过 ZCode 一级导航的容量，平铺会让侧栏过长。

### 2.3 列表分区用 tab 而非可折叠分区（受宿主约束）

ZCode 把内容分为 Projects / Conversations 两个可拖拽重排的分区；
本插件用「任务 / 频道 / 定时」三个 tab。

原因：**DSH 的会话与频道是两个独立数据域**（会话属 workspace，频道属 IM），
不能像 ZCode 那样统一在一个可重排列表里分区。tab 是 DSH 数据模型的直接映射。

### 2.4 任务分区与两级树（受宿主约束）

ZCode 的任务列表有四个并列区域（置顶 / 时间线 / 分组 / 归档）；
本插件是「工作区 → 会话」两级树。

原因：**DSH 的组织主轴是 workspace**，会话挂在 workspace 之下。ZCode 的
「任务时间线」对应任务的创建时间排序，DSH 没有等价的一级对象。

### 2.5 置顶 / 分组的对象不同（受宿主约束，语义相反）

这是**最容易被误判为 bug** 的一条：

- ZCode：置顶与分组作用于**任务**
- 本插件：置顶与分组作用于**项目 / 工作区**

原因：DSH 里 workspace 才是用户手工组织的单位，会话由系统按时间生成；
ZCode 则相反，task 是用户组织单位。**两者语义相反源于数据模型差异，不是实现错误。**

从 ZCode 迁移过来的用户，这一条的肌肉记忆会对不上——样式层无法解决，只能靠文档声明。

### 2.6 分组能力缺口（确实待办）

ZCode 的组支持颜色、sticky 组头、拖任务入组、空组投放区、虚拟列表。
本插件的项目分组目前缺：**组颜色、sticky 组头、虚拟列表**。

状态：待办，不在本次 P1 范围内。

## 三、结论速查

| 分类 | 条目 | 可否改动 |
| --- | --- | --- |
| 有意保留（设计取舍） | 折叠轨内容、扩展二级分组 | 可改，但需先确认功能可达性不受损 |
| 受宿主数据模型约束 | 列表分区形式、任务分区形式、置顶/分组对象语义 | **不可改**，改则与 DSH 数据模型冲突 |
| 确实待办 | 组颜色、sticky 组头、虚拟列表 | 可改，属功能增强 |

维护提示：改动侧栏结构前，先确认目标差异属于哪一类。属于第二类的，
不是「修 bug」，而是「要求宿主换数据模型」。
